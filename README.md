# 果忍對決：單人練習／雙人體感切水果

離線優先的本機 Web 遊戲，以 Mac 內建、外接或 iPhone 接續互通相機辨識玩家全身關節。提供單人練習、45 秒雙人休閒對戰與 13–30 人正式賽事，包含三種難度、獨立賽道、音效、換邊、排行榜、決賽、同分加賽與中斷恢復。

> 目前是可試玩及現場驗證的活動版。自動化檢查已建立；實體攝影機效能、60 分鐘壓力與 24 人坐／站姿平衡驗證仍待完成。在放行條件通過前，不應將坐姿與站姿成績用於正式共榜比較。

## 環境需求

- macOS 與 Node.js 22.12 以上。
- 支援攝影機、Web Worker、WebAssembly 與 WebGL 的新版 Chrome 或 Edge。
- 可拍到玩家頭、肩、手肘、手腕、手掌及上半身活動範圍的廣角攝影機；建議 720p30 輸入、1080p 大螢幕輸出。
- 穩定照明、左右地貼、中央禁區、安全伸手空間與一位主持人。

## 安裝與啟動

首度安裝（需要連線取得 npm 套件）：

```bash
npm install
```

開發模式：

```bash
npm run dev
```

請開啟 Vite 顯示的 `http://127.0.0.1:...`。攝影機 API 需要安全環境，`localhost` 與 `127.0.0.1` 可供本機使用；不要直接雙擊 `index.html`。

活動用生產版：

```bash
npm run start
```

此指令會先建置，再於 `http://127.0.0.1:4173` 啟動本機伺服器，並在 macOS 嘗試開啟瀏覽器。也可在 Finder 雙擊 [start-game.command](./start-game.command)；第一次仍須先執行 `npm install`。若 macOS 阻擋腳本，可右鍵選「開啟」，或先執行：

```bash
chmod +x start-game.command
```

其他常用指令：

```bash
npm run build       # 型別檢查並產生 dist/
npm run serve       # 提供已建置的 dist/
npm run preview     # 以 Vite 預覽生產版
```

## 攝影機、隱私與離線運作

- 首頁會列出可用鏡頭；點「連接攝影機」後才會要求權限。首次授權前瀏覽器通常隱藏裝置名稱，授權後按「重新搜尋」即可選擇 Mac、外接鏡頭或 iPhone。
- 影像、姿態骨架與手掌軌跡只在本機記憶體處理；不錄影、不上傳、不加入第三方分析。
- MediaPipe Lite／Full 模型位於 `public/models/`，WASM 位於 `public/vendor/mediapipe/`；`npm install` 會把套件內 WASM 同步到本機公開資產目錄。
- 依賴與資產安裝完成後，遊戲執行不需要對外網路。斷網活動前，請先以生產版完整啟動一次確認資產齊全。
- 「滑鼠示範」可演練介面、計分與賽事流程，但不能取代實體攝影機追蹤與平衡驗收。

### 使用 iPhone 16 Pro

1. 依 [Apple 接續互通相機說明](https://support.apple.com/zh-tw/102546)，讓 Mac 與 iPhone 登入相同 Apple 帳號並開啟雙重認證、Wi‑Fi、藍牙與 iPhone 的「接續互通相機」。
2. 將 iPhone 鎖定、橫放並牢固固定，後置鏡頭朝向玩家。活動現場建議使用 USB 連線、在 iPhone 上信任這台 Mac，並避免同時使用 AirPlay 或並行功能。
3. 在首頁按「重新搜尋」，選擇標有「iPhone 接續互通」的項目，再按「連接攝影機」。系統會優先排列偵測到的 iPhone 鏡頭，並以柔性的 1280×720、30 FPS 作為理想輸入。

iPhone 的後置鏡頭畫質、廣角與擺位可能提高 RGB 姿態辨識成功率，但瀏覽器的 `getUserMedia` 只會取得一般彩色視訊軌，不能取得 iPhone LiDAR 深度圖。[W3C 網頁深度串流草案](https://www.w3.org/TR/mediacapture-depth/)已因缺乏實作而停止；若要真正使用 LiDAR，必須另做原生 iOS App，透過 [AVFoundation LiDAR 深度擷取](https://developer.apple.com/documentation/AVFoundation/capturing-depth-using-the-lidar-camera) 後再設計本機資料橋接，這不包含在目前純 Web 版本中。

## 多關節辨識

- 推論器會依後端與實測延遲自動選擇負載：GPU 以高精度 **Full／3 候選／768px** 開始，CPU 後援使用低延遲 **Lite／2 候選／640px**。兩者都輸出標準 33 個姿態點；這是模型精度與負載取捨，不是減少手部關節。
- 遊戲品質與身分判定集中使用 17 個核心錨點：鼻尖、雙耳、雙肩、雙肘、雙腕、每手拇指／食指／小指共 6 點及雙髖。眼睛、嘴巴與下肢不參與這個上半身切擊遊戲的品質分數。
- 雙髖短暫離框時，可由頭、肩、肘與手部維持上半身追蹤。兩個以上手部點可信時，刀點直接取拇指／食指／小指末端群集；手腕只做解剖與連續性驗證，不再把圓環往前臂方向拉回。單一手指或腕點離群不會把刀點帶走，完全不可見時不會推測幽靈刀點。
- 遊戲會顯示 32px 玩家色圓環、白色外框、白色中心點及 48px 深色光暈；圓環就是玩家應對準水果的切擊基準。所有玩家使用相同的 32px 掃掠碰撞半徑。
- 單人與雙人共用相同的垂直可達映射：手指末端在肩膀上下約一個軀幹長時，分別到達畫面 `5.5%` 與 `94.5%`；上下安全邊界能容納完整 48px 光暈，因此不需把手伸出鏡頭。
- GPU 模式最多保留 3 位姿態候選，足以鎖定兩名玩家並排除一名觀眾；效能吃緊時自動降為 2。CPU 後援通常為 2，只有在延遲健康但登記玩家被其他入鏡者擠掉時才暫升為 3。系統先為畫面中每個頭部建立不依模型順序的短期軌跡 ID，再於校正時把兩位玩家原子綁定到各自軌跡並封存頭肩比例；已知觀眾的軌跡不可轉成玩家。
- 影格最長邊依實測狀態在 512–960px 間調整：延遲健康但持續缺少第二人時提高細節，p95 過高時降低負載。Worker 只回傳上述 17 個遊戲錨點以降低資料複製，模型內部仍推論 33 點。
- 雙人廣角畫面只要雙肩與雙肘等上半身結構穩定，不會再因非主手、耳部或髖部低信心而同時淘汰兩人；真正切擊仍另外要求指定主手的肩–肘–腕／手指鏈通過安全門檻。
- 校正頁會常駐顯示原始人體數、通過候選、本幀分配／身份封存、主手信心、FPS 與 p95。玩家頭部旁的固定色鎖定環與姓名不會隨模型候選順序換色；未分配觀眾一律顯示灰色。
- 動作的拍攝時間與結果抵達時間分開處理：拍攝時間只計算 100ms 掃掠速度，抵達時間控制 180ms 顯示與一次性碰撞。因此雙人推論較慢時不會「結果一到就過期」，舊軌跡也不會重播得分。
- 兩位玩家交叉或短暫重疊時，不確定的刀點會立即停用，但已封存身份不會自動解鎖。手臂離框而頭部仍在時只停刀、不換人；頭部持續失追 1.4 秒會安全暫停，長時間失追後必須重新校正，觀眾即使站入原位置也不能直接接管分數。
- 頭部錨點只使用本機 Pose landmarks 的空間與身體比例，不辨識臉孔、不建立生物特徵，也不保存影像。
- 高品質影格會持續慢速更新肩寬與軀幹尺度，校準被限制在開局基準的 ±10%，避免單幀跳動、無界漂移或靠前後移動取得不合理優勢。
- Worker 的候選門檻調整為 detection／presence `0.35`、tracking `0.40`；刀尖另有較嚴格的關節品質、安全暫停與重新校正規則。

## 玩法

### 單人練習

- 使用完整畫面及指定單一主手，可選姓名、左／右手、站／坐姿、Easy／Normal／Hard 與 30／45／60 秒。
- 具有獨立單人追蹤、校正、全寬水果場、HUD、安全暫停及成績頁；成績顯示分數、命中率、最長連擊與炸彈數，但不寫入正式賽排行榜。
- 若第二人進入畫面，系統會維持已校準的單人身分並將對方視為觀眾；只有練習玩家本人持續失追才會暫停。

### 休閒對戰

- 兩人同時進行 45 秒，每人自選一隻指定主手，畫面與得分最多各一個切點（全場固定最多兩點）。
- 可自由選擇 Easy、Normal 或 Hard，適合暖身、試玩及設備檢查。
- 每位玩家只能切自己顏色半場的水果，中央為安全區。

### 正式賽事

- 建立 13–30 人名單，每行格式為 `名稱 | R 或 L | standing 或 seated`，例如 `小明 | R | standing`。活動開始後名單與難度鎖定；不同難度不共榜。
- 名單隨機配對；奇數人時加入不計排名的陪玩者，以維持雙人辨識條件。
- 每組先進行 10 秒不計分練習，再玩兩個 25 秒小局。兩局間需實際交換左右位置、休息至少 30 秒並重新校正。
- 正式賽只接受登記的單一主手。預賽兩局加總後前二名進入冠軍賽；冠軍賽為兩個 30 秒新腳本小局，冠軍只看冠軍賽總分。
- 同分先比炸彈誤觸較少、再比漏果較少；仍同分時進行兩個 10 秒新腳本小局並換邊。

### 計分與難度

- 普通水果 100 分。連擊 5–9 顆時每顆加 20 分，10–19 顆加 40 分，20 顆以上加 60 分。
- 漏果只中斷連擊；炸彈扣 200 分並將連擊歸零，總分不低於零。
- 揮動速度與一次多切不額外加分，避免裝置幀率成為優勢。

| 難度 | 每人／25 秒 | 同時上限 | 特性 |
|---|---:|---:|---|
| Easy | 20 水果／1 炸彈 | 2 | 大型水果、長反應窗 |
| Normal | 28 水果／3 炸彈 | 3 | 中等速度、連續路徑 |
| Hard | 36 水果／5 炸彈 | 4 | 小型水果、短反應窗 |

## 主持人操作與中斷恢復

1. 連接正確鏡頭，確認兩人的頭、肩、肘、手掌、髖部與完整擺動範圍入鏡，再進入全螢幕；校正階段先讓觀眾退開，等兩人的頭部旁各自出現固定色「🔒」環，才代表雙人身份已原子封存。
2. GPU 模式可從最多 3 位候選鎖定兩名玩家並忽略一名觀眾；CPU／降載模式通常先保留兩名，延遲足夠時可自動暫升三名。仍應避免觀眾接近鏡頭或遮住玩家。玩家不跨中央區、不跳躍；坐姿玩家固定椅腳，輪椅鎖定煞車。
3. 小局結束後，主持人只能「確認成績」，或填寫技術理由後「作廢並重跑」；不能手動改分。作廢時系統改抽未曝光腳本。
4. 正式賽事快照以 IndexedDB 儲存在目前瀏覽器與網頁來源中。重新整理後，從首頁「恢復賽事」回到最後已儲存狀態；進行中且未確認的小局應依畫面提示重新校正或重跑。
5. 恢復時須使用相同瀏覽器使用者資料與相同網址。無痕模式、清除網站資料或點「刪除紀錄」會使本機快照消失。

24 人門檻為：各難度坐／站姿平均分比 `0.95–1.05`、命中率差不超過 3 個百分點、炸彈誤觸差不超過 1 個百分點，且兩組有效追蹤率都至少 `98.5%`。任一難度未過時，應繼續調整並單獨驗證，不開放該難度坐／站共榜。

程式內已提供 `src/core/balance-release-gate.ts` 供匯入現場量測資料，並以 `src/core/script-pool-simulator.ts` 對 48／8／16 組腳本池執行同難度平均分 ±2% 的離群檢查。這兩者是放行工具，不代表尚未執行的真人測試已通過。

## 疑難排解

- **無法開啟鏡頭**：確認使用 `localhost`／`127.0.0.1`，並在「系統設定 → 隱私權與安全性 → 相機」允許瀏覽器。關閉 Zoom 等可能占用鏡頭的程式，重新整理後再連接。
- **追蹤不穩或自動暫停**：提高均勻照明，讓玩家的頭、雙肩、手肘、手腕與手掌清楚入鏡，能拍到雙髖更佳；雙人時加大左右間距。短暫重疊不會暫停，但若觀眾遮住玩家超過約 1.4 秒仍會安全暫停。
- **刀點仍和手指末端有落差**：重新進入校正，保持正面、肩膀與主手完整入鏡。圓環採身體比例映射，不會逐像素覆蓋攝影機中的手，但主手在肩膀上下約一個軀幹長即可涵蓋安全遊戲區，不應再把手伸出畫面。
- **觀眾靠近或玩家被遮住**：先確認玩家頭部旁仍是原本顏色與姓名的「🔒」環；觀眾應顯示灰色。若頭部被完全遮住，系統會停刀並在持續失追後要求重新校正，而不猜測身份。Pose 錨點不是臉部辨識，因此外人與玩家完全重疊時只能安全暫停，現場仍應避免觀眾站到玩家身前。
- **找不到 iPhone 鏡頭**：確認兩台裝置符合 Apple 接續互通條件，iPhone 已鎖定且靠近 Mac；先連接任一鏡頭完成瀏覽器授權，再回首頁按「重新搜尋」。活動現場可改接 USB 並重新選擇。
- **想使用 LiDAR**：目前網頁版無法取得深度資料；選到 iPhone 代表使用其 RGB 彩色鏡頭，不代表 LiDAR 已啟用。真正的深度辨識需要另開發原生 iOS 伴隨 App。
- **畫面卡頓**：將攝影機設為 720p30，關閉其他視訊程式與高負載分頁。按 `Option + D` 可查看 GPU／CPU、推論 FPS、推論 p95、完整 pipeline p95 與各階段延遲，再於目標 Mac 重做效能檢查。
- **沒有聲音**：先在頁面點擊「開始」或其他按鈕解鎖 Web Audio，確認未靜音且系統輸出裝置正確。
- **找不到賽事紀錄**：確認沒有更換瀏覽器使用者、網址或連接埠，且未清除網站資料。
- **連接埠 4173 被占用**：使用 `PORT=4174 npm run serve`，再開啟 `http://127.0.0.1:4174`。

## 主要架構

- Vite + TypeScript + Phaser 3.90：遊戲畫面、物理與主持人 DOM 介面。
- MediaPipe Pose Landmarker Web Worker：GPU Full／CPU Lite 自適應負載、模型 33 點、17 點肢體品質判定、單／雙人主體身分追蹤、觀眾排除與手掌軌跡。
- IndexedDB：本機賽事快照與重新整理恢復。
- Web Audio：可重疊播放的切果、炸彈、連擊、倒數及勝利程序音效。
