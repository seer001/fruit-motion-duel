# 果忍對決：單人練習／雙人體感切水果

離線優先的本機 Web 遊戲，以 Mac 內建、外接或 iPhone 接續互通相機辨識玩家全身關節。提供單人練習、45 秒雙人休閒對戰與 13–30 人正式賽事，包含三種難度、獨立賽道、音效、換邊、排行榜、決賽、同分加賽與中斷恢復。

> 目前是可試玩及現場驗證的活動版。自動化檢查能驗證設定、追蹤、中央安全區與遊戲流程，但不能代替真實雙人鏡頭。目標 Mac、實體攝影機、雙人校正／追蹤、720p30 延遲、60 分鐘壓力與 24 人坐／站姿平衡仍須人工驗收。在放行條件通過前，不應將坐姿與站姿成績用於正式共榜比較。

## 環境需求

- macOS 與 Node.js 22.12 以上。
- 支援攝影機、Web Worker、WebAssembly 與 WebGL 的新版 Chrome 或 Edge。
- 可拍到玩家頭、肩、手肘、手腕、手掌及上半身活動範圍的廣角攝影機；建議 720p30 輸入、1080p 大螢幕輸出。
- 穩定照明、左右地貼、中央禁區、安全伸手空間與一位主持人。

## 安裝與啟動

首度安裝（需要連線取得 npm 套件）：

```bash
npm install
```

開發模式：

```bash
npm run dev
```

請開啟 Vite 顯示的 `http://127.0.0.1:...`。攝影機 API 需要安全環境，`localhost` 與 `127.0.0.1` 可供本機使用；不要直接雙擊 `index.html`。

活動用生產版：

```bash
npm run start
```

此指令會先建置，再於 `http://127.0.0.1:4173` 啟動本機伺服器，並在 macOS 嘗試開啟瀏覽器。也可在 Finder 雙擊 [start-game.command](./start-game.command)；第一次仍須先執行 `npm install`。若 macOS 阻擋腳本，可右鍵選「開啟」，或先執行：

```bash
chmod +x start-game.command
```

其他常用指令：

```bash
npm run build       # 型別檢查並產生 dist/
npm run serve       # 提供已建置的 dist/
npm run preview     # 以 Vite 預覽生產版
```

## 攝影機、隱私與離線運作

- 首頁會列出可用鏡頭；點「連接攝影機」後才會要求權限。首次授權前瀏覽器通常隱藏裝置名稱，授權後按「重新搜尋」即可選擇 Mac、外接鏡頭或 iPhone。
- 影像、姿態骨架與手掌軌跡只在本機記憶體處理；不錄影、不上傳、不加入第三方分析。
- MediaPipe Lite／Full 模型位於 `public/models/`，WASM 位於 `public/vendor/mediapipe/`；`npm install` 會把套件內 WASM 同步到本機公開資產目錄。
- 依賴與資產安裝完成後，遊戲執行不需要對外網路。斷網活動前，請先以生產版完整啟動一次確認資產齊全。
- 「滑鼠示範」可演練介面、計分與賽事流程，但不能取代實體攝影機追蹤與平衡驗收。

### 使用 iPhone 16 Pro

1. 依 [Apple 接續互通相機說明](https://support.apple.com/zh-tw/102546)，讓 Mac 與 iPhone 登入相同 Apple 帳號並開啟雙重認證、Wi‑Fi、藍牙與 iPhone 的「接續互通相機」。
2. 將 iPhone 鎖定、橫放並牢固固定，後置鏡頭朝向玩家。活動現場建議使用 USB 連線、在 iPhone 上信任這台 Mac，並避免同時使用 AirPlay 或並行功能。
3. 在首頁按「重新搜尋」，選擇標有「iPhone 接續互通」的項目，再按「連接攝影機」。系統會優先排列偵測到的 iPhone 鏡頭，並以柔性的 1280×720、30 FPS 作為理想輸入。

iPhone 的後置鏡頭畫質、廣角與擺位可能提高 RGB 姿態辨識成功率，但瀏覽器的 `getUserMedia` 只會取得一般彩色視訊軌，不能取得 iPhone LiDAR 深度圖。[W3C 網頁深度串流草案](https://www.w3.org/TR/mediacapture-depth/)已因缺乏實作而停止；若要真正使用 LiDAR，必須另做原生 iOS App，透過 [AVFoundation LiDAR 深度擷取](https://developer.apple.com/documentation/AVFoundation/capturing-depth-using-the-lidar-camera) 後再設計本機資料橋接，這不包含在目前純 Web 版本中。

## 效能設定與 renderer 生命週期

首頁的「效能與畫質」提供四種內建預設；`Auto` 從平衡值開始，再依持續延遲與辨識狀態調整，不會因單一影格立即切換。

| 預設 | 姿態模型 | 推論最長邊 | 推論目標 | 候選上限 | 遊戲 renderer | 抗鋸齒 | 效果 | 骨架更新 |
|---|---|---:|---:|---:|---:|---|---|---:|
| Auto | 自動（GPU Full／CPU Lite） | 640px 起 | 20 FPS 起 | 2 起 | 45 FPS 起 | 開 | Medium | 15 FPS |
| 效能優先 | Lite | 512px | 15 FPS | 2 | 30 FPS | 關 | Low | 10 FPS |
| 平衡 | 自動（GPU Full／CPU Lite） | 640px | 20 FPS | 2 | 45 FPS | 開 | Medium | 15 FPS |
| 畫質優先 | Full（CPU 回退仍用 Lite） | 768px | 30 FPS | 3 | 60 FPS | 開 | High | 30 FPS |

「進階單項設定」可調整 Lite／Full／自動模型、512／640／768／960px、15／20／24／30 FPS 推論、2／3 候選、觀眾候選保留、30／45／60 FPS renderer、抗鋸齒、攝影機背景、Off／Low／Medium／High 效果、骨架更新率與 CSS 模糊。改動進階值會標示為「進階自訂」；攝影機背景是可覆寫任一預設的獨立選項。關閉時攝影機仍持續供本機姿態辨識使用，遊戲圖層則改為不透明背景。

- 設定以版本化 `localStorage` 只保存在目前裝置，不寫入賽事快照或分數；損壞、過期或非法值會回復 Auto。按「恢復自動設定」可清除本機自訂值。
- 效能設定只能在沒有進行中校正、倒數或小局時套用。模型偏好變更需重新初始化 Vision Worker；透明與抗鋸齒屬於 renderer 初始化設定，只會在安全畫面銷毀並重建。render FPS、效果與骨架更新率可由 Auto 在執行中調整，不需重建 renderer。
- Auto 的跨系統降載順序固定為：平衡起點（45 FPS／Medium／骨架 15 FPS）→ 先降效果與骨架（Low／10 FPS）→ 再降 renderer 至 30 FPS → 最後才把推論目標降至 15 FPS 並允許 Vision 降低尺寸或候選負載。連續 12 個壓力樣本才下降一階，階段間至少冷卻 24 個樣本；恢復一階需連續 36 個健康樣本，從平衡升至品質則需 72 個。Auto 階段只存在於執行期，不會覆寫已保存的 Auto 設定。
- `FruitDuelGame` 不再於應用啟動時建立。只有準備倒數／進入遊戲時才延後建立並 wake；首頁、設定、校正、換邊、結果與排行榜畫面不存在 renderer，或使用會停止 Phaser 全域 `requestAnimationFrame` 的 sleep。離開遊戲畫面後立即 sleep；這與只暫停 Scene 不同，不會讓非遊戲畫面留下常駐 60 FPS WebGL loop。

## 多關節辨識

- 每個解碼完成的攝影機影格都以**整張影像**送入 Pose Landmarker，而且每幀最多只做一次姿態推論。一次結果產生多位候選後，才進行品質篩選、左右賽道分配與身份追蹤；雙人模式不會把影像裁成左右兩張，也不會為兩位玩家各推論一次。Worker 同時只允許一個推論進行，繁忙時只保留最新待處理影格，不堆積舊影格佇列。
- 模型、推論尺寸、目標 FPS 與候選上限由效能預設或進階設定決定；自動模型優先嘗試 GPU Full，失敗時回退 CPU Lite。兩種模型內部都輸出標準 33 個姿態點；這是精度與負載取捨，不是減少手部關節。
- 遊戲品質與身分判定集中使用 17 個核心錨點：鼻尖、雙耳、雙肩、雙肘、雙腕、每手拇指／食指／小指共 6 點及雙髖。眼睛、嘴巴與下肢不參與這個上半身切擊遊戲的品質分數。
- 雙髖短暫離框時，可由頭、肩、肘與手部維持上半身追蹤。至少兩個手部點可信時，先排除單一跳點，再從拇指／食指／小指中取離肘部（備援為肩膀）最遠的當幀實測點作為刀點；在畫面邊緣只剩一個手部點時，必須由可信手腕與手臂鏈共同驗證才採用。刀點座標必定等於模型當幀回傳的某一手部點，不取群集中心、不外推手指或手持工具；手腕也消失時不會從單一手點推測幽靈刀點。
- 水平刀點以「主手側肩膀」為賽道中點，不再以身體中心為零點；右手切左側水果（左手則相反）時只需伸向身體中線附近，避免跨過對側肩膀造成遮擋與左右點混淆。若交叉動作中肘、腕短暫被擋住，三個當幀主手端點與同側肩膀仍可信時可繼續供應刀點；不完整手點仍會停刀。
- 遊戲會顯示 32px 玩家色圓環、白色外框、白色中心點及 48px 深色光暈；圓環就是玩家應對準水果的切擊基準。所有玩家使用相同的 32px 掃掠碰撞半徑。
- 單人與雙人共用相同的垂直可達映射：手指末端在肩膀上下約一個軀幹長時，分別到達畫面 `5.5%` 與 `94.5%`；上下安全邊界能容納完整 48px 光暈，因此不需把手伸出鏡頭。
- 一般雙人辨識保留 2 位候選；畫質預設、觀眾候選保留，或 Auto 在延遲健康但持續缺少登記玩家時可使用 3 位。系統先為每個頭部建立不依模型候選順序的短期軌跡 ID，再於校正時綁定玩家；已知觀眾的軌跡不可轉成玩家。
- 固定預設使用表列的尺寸與候選上限；只有 Auto 會依持續狀態在 512–960px、2–3 位候選間調整。升降載具有觀察窗、冷卻時間與遲滯，不因單一影格切換。Worker 只回傳上述 17 個遊戲錨點以降低資料複製，模型內部仍推論 33 點。
- 雙人廣角畫面只要雙肩與雙肘等上半身結構穩定，不會再因非主手、耳部或髖部低信心而同時淘汰兩人；真正切擊仍另外要求指定主手的肩–肘–腕／手指鏈通過安全門檻。
- 動作的拍攝時間與結果抵達時間分開處理：拍攝時間只計算 100ms 掃掠速度，抵達時間控制 180ms 顯示與一次性碰撞。因此雙人推論較慢時不會「結果一到就過期」，舊軌跡也不會重播得分。
- 兩位玩家交叉或短暫重疊時，不確定的刀點會立即停用，但已封存身份不會自動解鎖。手臂離框而頭部仍在時只停刀、不換人；頭部持續失追 1.4 秒會安全暫停，長時間失追後必須重新校正，觀眾即使站入原位置也不能直接接管分數。
- 頭部錨點只使用本機 Pose landmarks 的空間與身體比例，不辨識臉孔、不建立生物特徵，也不保存影像。
- 高品質影格會持續慢速更新肩寬與軀幹尺度，校準被限制在開局基準的 ±10%，避免單幀跳動、無界漂移或靠前後移動取得不合理優勢。
- Worker 的候選門檻調整為 detection／presence `0.35`、tracking `0.40`；刀尖另有較嚴格的關節品質、安全暫停與重新校正規則。

### 左右獨立校正、中央安全區與診斷

- 雙人賽道以正規化相機座標分成左側 `0.08–0.46`、中央安全區 `0.46–0.54`、右側 `0.54–0.92`；邊界屬於中央安全區。校正候選的頭部中心必須位在自己的左右區域，落在中央、外側或分配有歧義時一律不取樣，不任意挑一人補位。
- 左右玩家各自累積 **16 個有效樣本**；某一側缺人、品質不足或身份變動，不會停止或清空另一側的進度。每個緩衝區綁定穩定的頭部軌跡 ID；ID 改變時只重置該側，已完成的側別則封存。兩份校正資料都完成後才原子鎖定身份，接著兩位玩家的指定主手都須連續 3 幀達到 `0.55` 信心才可開始。
- 每個有效頭部樣本至少要有兩個可信頭部點（鼻尖搭配耳朵，或雙耳），單一頭點不能取樣。在 16 個樣本中取得至少 **6 組可信雙耳距**即可使用耳距；不足 6 組時，只有肩寬、頭肩偏移與肩／軀幹比例持續穩定才採用肩軀幹 fallback，並記錄 fallback 來源，不憑空補造耳距。
- 遊戲中身份持續綁定已封存的頭部軌跡，短暫接近中央不會交換身份。刀點最新位置落在中央或對手側時不參與碰撞；回到自己側時只保留新產生、連續且同側的軌跡尾段，避免跨越中央的舊線段補切水果。單人練習仍保留全寬活動與完整刀軌。
- 「辨識／校正診斷」按左右分卡顯示原始候選、通過候選、分配與歧義、頭部軌跡 ID、`n/16` 樣本、耳距 `n/6` 或 fallback、身份鎖定及主手信心／就緒狀態。阻擋開始的辨識原因依優先順序顯示。
- 「效能診斷」另行顯示目前預設、Auto 升降載、實際 backend／模型／尺寸／候選上限、推論 FPS／p95，以及 renderer FPS、抗鋸齒、透明背景與效果等級。效能警示不會覆蓋辨識原因，也不會直接解除身份或阻止校正；主持人可分別判斷「看不到人」與「裝置太慢」。

## 玩法

### 單人練習

- 使用完整畫面及指定單一主手，可選姓名、左／右手、站／坐姿、Easy／Normal／Hard 與 30／45／60 秒。
- 具有獨立單人追蹤、校正、全寬水果場、HUD、安全暫停及成績頁；成績顯示分數、命中率、最長連擊與炸彈數，但不寫入正式賽排行榜。
- 若第二人進入畫面，系統會維持已校準的單人身分並將對方視為觀眾；只有練習玩家本人持續失追才會暫停。

### 休閒對戰

- 兩人同時進行 45 秒，每人自選一隻指定主手，畫面與得分最多各一個切點（全場固定最多兩點）。
- 可自由選擇 Easy、Normal 或 Hard，適合暖身、試玩及設備檢查。
- 每位玩家只能切自己顏色半場的水果，中央為安全區。

### 正式賽事

- 建立 13–30 人名單，每行格式為 `名稱 | R 或 L | standing 或 seated`，例如 `小明 | R | standing`。活動開始後名單與難度鎖定；不同難度不共榜。
- 名單隨機配對；奇數人時加入不計排名的陪玩者，以維持雙人辨識條件。
- 每組先進行 10 秒不計分練習，再玩兩個 25 秒小局。兩局間需實際交換左右位置、休息至少 30 秒並重新校正。
- 正式賽只接受登記的單一主手。預賽兩局加總後前二名進入冠軍賽；冠軍賽為兩個 30 秒新腳本小局，冠軍只看冠軍賽總分。
- 同分先比炸彈誤觸較少、再比漏果較少；仍同分時進行兩個 10 秒新腳本小局並換邊。

### 計分與難度

- 普通水果 100 分。連擊 5–9 顆時每顆加 20 分，10–19 顆加 40 分，20 顆以上加 60 分。
- 漏果只中斷連擊；炸彈扣 200 分並將連擊歸零，總分不低於零。
- 揮動速度與一次多切不額外加分，避免裝置幀率成為優勢。

| 難度 | 每人／25 秒 | 同時上限 | 特性 |
|---|---:|---:|---|
| Easy | 20 水果／1 炸彈 | 2 | 大型水果、長反應窗 |
| Normal | 28 水果／3 炸彈 | 3 | 中等速度、連續路徑 |
| Hard | 36 水果／5 炸彈 | 4 | 小型水果、短反應窗 |

## 主持人操作與中斷恢復

1. 連接正確鏡頭，確認兩人的頭、肩、肘、手掌、髖部與完整擺動範圍入鏡，再進入全螢幕；校正階段先讓觀眾退開。左右會各自累積 16 個有效樣本，耳距不足 6 組時會檢查穩定肩軀幹 fallback；等兩側都完成、身份原子封存且兩位主手就緒後，頭部旁才會維持固定色「🔒」環。
2. 候選上限由目前效能預設或進階設定決定：一般為 2 位，畫質優先、觀眾候選保留或健康的 Auto 辨識救援可使用 3 位；無論候選數，整張相機影格每幀仍最多只推論一次。現場仍應避免觀眾接近鏡頭或遮住玩家。玩家不跨中央區、不跳躍；坐姿玩家固定椅腳，輪椅鎖定煞車。
3. 小局結束後，主持人只能「確認成績」，或填寫技術理由後「作廢並重跑」；不能手動改分。作廢時系統改抽未曝光腳本。
4. 正式賽事快照以 IndexedDB 儲存在目前瀏覽器與網頁來源中。重新整理後，從首頁「恢復賽事」回到最後已儲存狀態；進行中且未確認的小局應依畫面提示重新校正或重跑。
5. 恢復時須使用相同瀏覽器使用者資料與相同網址。無痕模式、清除網站資料或點「刪除紀錄」會使本機快照消失。

## 疑難排解

- **無法開啟鏡頭**：確認使用 `localhost`／`127.0.0.1`，並在「系統設定 → 隱私權與安全性 → 相機」允許瀏覽器。關閉 Zoom 等可能占用鏡頭的程式，重新整理後再連接。
- **追蹤不穩或校正停住**：先看左右「辨識／校正診斷」是哪一側未達 `n/16`、耳距 `n/6` 或穩定肩軀幹 fallback，再提高均勻照明，讓玩家的鼻尖／耳朵、雙肩、手肘、手腕與手掌清楚入鏡，能拍到雙髖更佳；雙人時加大左右間距並離開中央安全區。短暫重疊不會交換身份，但若觀眾遮住玩家超過約 1.4 秒仍會安全暫停。
- **刀點仍和手部最外側有落差**：重新進入校正，保持正面、肩膀與主手完整入鏡。判定原點會使用離手臂最遠的當幀實測手部點，不再使用點群中心且不做長度外推。圓環仍會經過身體比例映射；主手在肩膀上下約一個軀幹長即可涵蓋安全遊戲區，不應把手伸出畫面。
- **觀眾靠近或玩家被遮住**：先確認玩家頭部旁仍是原本顏色與姓名的「🔒」環；觀眾應顯示灰色。若頭部被完全遮住，系統會停刀並在持續失追後要求重新校正，而不猜測身份。Pose 錨點不是臉部辨識，因此外人與玩家完全重疊時只能安全暫停，現場仍應避免觀眾站到玩家身前。
- **找不到 iPhone 鏡頭**：確認兩台裝置符合 Apple 接續互通條件，iPhone 已鎖定且靠近 Mac；先連接任一鏡頭完成瀏覽器授權，再回首頁按「重新搜尋」。活動現場可改接 USB 並重新選擇。
- **想使用 LiDAR**：目前網頁版無法取得深度資料；選到 iPhone 代表使用其 RGB 彩色鏡頭，不代表 LiDAR 已啟用。真正的深度辨識需要另開發原生 iOS 伴隨 App。
- **畫面卡頓**：先選「效能優先」或回到 Auto，必要時關閉攝影機背景、抗鋸齒、CSS 模糊並降低效果；同時將攝影機設為 720p30，關閉其他視訊程式與高負載分頁。按 `Option + D` 查看獨立的效能診斷，包括實際 backend／模型／尺寸／候選、推論 FPS／p95 與 renderer 狀態；辨識／校正阻擋原因會留在另一張診斷卡，不會被效能警示覆蓋。
- **沒有聲音**：先在頁面點擊「開始」或其他按鈕解鎖 Web Audio，確認未靜音且系統輸出裝置正確。
- **找不到賽事紀錄**：確認沒有更換瀏覽器使用者、網址或連接埠，且未清除網站資料。
- **連接埠 4173 被占用**：使用 `PORT=4174 npm run serve`，再開啟 `http://127.0.0.1:4174`。

## 主要架構

- Vite + TypeScript + Phaser 3.90：主持人 DOM 介面，以及只在倒數／遊戲需要時延後建立、可停止全域 RAF 並依安全設定變更重建的遊戲 renderer。
- MediaPipe Pose Landmarker Web Worker：整張攝影機影格每幀最多一次推論、單一進行中工作與最新影格覆寫、GPU Full／CPU Lite 執行時設定、模型 33 點、17 點肢體品質判定、單／雙人主體身分追蹤、觀眾排除與手掌軌跡。
- IndexedDB：本機賽事快照與重新整理恢復。
- Web Audio：可重疊播放的切果、炸彈、連擊、倒數及勝利程序音效。
